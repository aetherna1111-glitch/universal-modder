# ADR-0004: Story phases are administrator-controlled; clues are authored and gated without override

Date: 2026-10-12 · Status: accepted

## Decision

1. `StoryController.setPhase` (op 4) is the normal way the story moves; it may go forwards or backwards and every
   change is recorded with reason and actor. A phase may opt into `autoAdvance: true`; then it is entered automatically
   when its explicit `conditions` hold (evaluated after Catalog, Progression and Story events). Default is `false`.
2. Clues are data (`Clue` + a lang text key). `mayReveal(clue)` is true only when the clue's phase has been reached and
   all its conditions hold. `reveal` is refused otherwise, for everyone: an early leak cannot be undone, so there is no
   force path (unlike Catalog verification and technology unlocks).
3. The controller exposes only read access to the future NPC/LLM layer (`mayReveal`, `revealable`, `revealedClues`).
   Writing story state from that layer is not an API that exists.

## Context

The owner's requirements: phases must be controllable by authorized administrators, persist across restarts, activate
according to explicit conditions, and "the language model must never independently advance the main plot, reveal
restricted information, or activate major events". Making admin control the default and automation opt-in per phase
satisfies both halves without a second configuration layer.

## Alternatives considered

- **Fully automatic story**: removes the admins' ability to pace a live server; rejected.
- **Clue override for admins**: convenient for testing, but it would make "revealed" ambiguous for the narrative and
  for the NPC; testing uses `setPhase` instead.
- **Clue text generated by the model**: rejected; lore truth must be authored (research set, `AI_NPC_TECHNICAL_RESEARCH.md` §4).

## Consequences

- Story conditions can reference progression prerequisites; the reload listener validates those ids with the same rules
  (a probe technology holding all story prerequisites is validated against the loaded progression definitions).
- Branch choice is admin-only in this slice; a civilization vote facility can later call `chooseBranch` through the
  same API.
- Schema v3 adds the `story` object; v1/v2 documents migrate (tests cover both).
